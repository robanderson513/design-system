# Audit: #14 — Add Recipe App Theme

## Ticket changes

This change adds the recipe app's primitive palette and an optional recipe brand override for the existing light/dark semantic themes. The default brand and its token aliases remain unchanged.

- Ticket: [#14](https://github.com/robanderson513/design-system/issues/14)
- Pull request: Not created.

### Files changed

- `tokens/primitives/colors.json`: adds sage, terracotta, harvest, and stone ramps with shades 50–950; the added deepest tones support darker neutral and selected-state surfaces.
- `tokens/semantic/colors.json`: adds recipe light/dark brand mappings for brand, surface, text, border, actions, and selected states; shared status roles remain inherited. Adds action text roles.
- `dist/index.js` and `dist/tokens.css`: expose the recipe values to CommonJS and CSS consumers and support `data-brand="recipe"` independently of `data-theme`.
- `preview.html`: adds brand/appearance selection, primitive ramp swatches, and resolved semantic role previews.
- `tests/theme.test.js`: checks ramp values, token reference resolution, compatibility, and recipe contrast pairings.
- `README.md`: documents recipe brand selection and behavior.

## Validation

- `node --test tests/theme.test.js` passed after adding 950 tones and using stone/sage 950 for recipe dark surfaces.
- All changed token JSON files parsed and semantic references resolved.
- The CommonJS entry point was checked for the default compatibility alias and recipe exports.
- Primary/secondary action text and primary/secondary/muted text against recipe surfaces were checked for 4.5:1 contrast.
- No package build or token generation command is available; shipped `dist` files were updated directly.
